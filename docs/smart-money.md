# 聪明钱观察的维护与数据边界

这次合并复用原观测 Site、登录、访问范围、模型设置及组件，不改变宏观数据空间。根路径是数据观察，`/smart-money` 是聪明钱观察；以后新增研究类别可沿用共享导航，再采用适合自身数据形状的存储。

## 源数据与持久化

迁入用户原有 `13f_workbench/index.html` 的 DATA JSON，文件生成时间2026-08-26。20家机构、79个机构季度、24,781条已存持仓，原值原字段保留；来源校验和见 `data/smart-money-provenance.json`。压缩初始快照仅由服务端 `lib/smart-money-storage.ts` 引入，不作为公开静态文件或客户端模块发布。

D1复用workspace表，以 `smart-money` 为独立主键；宏观仍为 `main`。R2写入 `smart-money/snapshots/<uuid>.json` 不可变快照，通过期望revision原子提交；并发冲突拒绝提交，保留上一有效数据。无需更改已有SQL迁移。首次读取使用随版本保存的初始快照，首次显式导入才写入R2。部署不重置两个分类的数据。

`GET /api/smart-money` 须登录，返回快照和所有者状态。`POST` 须所有者、同源、当前revision，流式限制25MB。未设置提交头时仅预览。HTML按固定数据标记提取JSON，不执行HTML、JavaScript或Python；不接受任意抓取URL。JSON字段、数值、目录、重复季度/证券与SEC来源均检查。

新文件补入遗漏历史；同一机构季度比较披露日期及机构updatedAt，旧数据不能降级替换，失败占位不能覆盖已有有效报告。相同机构key的CIK变化拒绝导入。更新器部分失败时显示失败保留状态；缺失季度画为缺口，不填零。不提供用旧快照回滚较新数据的隐式入口。

## 比较规则

- 同期聚合与反查严格使用所选季度。缺报机构显示空状态，用户可以在详情中主动选择旧季度。
- 跨机构证券身份是CUSIP + Put/Call + shareType；class为自由文本展示，不能用COM/COMMON等写法拆开同一CUSIP。
- 同期共同持仓只采用putCall为空且shareType=SH的记录。旧脚本可能已经将同一CUSIP的股票和期权合并，现有文件无法逆推拆分；带标记记录只展示原值，不给方向判断。
- 动作沿用原快照，但需连续季度、非异常持仓数量变化、相同证券类型及可核对前期数量。5倍以上/五分之一以下的持仓数变化作复核提示；缺失基期、前期截断无法确认、期权类型变化等均“待复核”。基期数量变化不显示。
- 总市值是整个申报值，明细可能是前500笔。搜索/共同持仓不代表全量覆盖；清仓最多原脚本保留200笔。市值变化含价格影响，股数变化未调整公司行动，不称为交易金额。

## 后续更新

继续运行原来的Mac更新命令，再在网站“聪明钱观察 → 数据与更新”上传更新后的index.html（或JSON）。原程序及其SEC邮箱配置保持原位置，不复制个人邮箱设置或执行文件到客户端。`scripts/export_smart_money.py` 可离线提取原HTML的JSON，网站本身也直接接受HTML。

原采集器仍有需修复之处：忽略13F-HR/A修订、只读recent、按价格比值猜美元单位、按CUSIP合并不同期权类型。这次迁移没有宣称重新核验79份原始XML。下一阶段如改建服务端SEC采集，应按官方申报版本处理单位、修订重述/新增、分页、限速、规范化证券类型与原始XML留存，验证后再替代原采集器。

当前13F没有无人值守定时抓取。宏观现有31个适配器和开页检查方式继续保留。不要将上传入口描述成自动更新。

## 智能分析与备份

两类共用 `/api/analyze`、所有者限制、密钥配置与每分钟3次额度限制。聪明钱通过domain与period在服务端重组上下文，包含各机构前10笔、共同持仓前20项、来源、缺报及复核标记；不接受客户端自称可信的数据。文件下载与只读 `read_smart_money_context` WebMCP使用相同口径。无模型密钥时明确提示，未执行付费试调用。

宏观备份入口只导出宏观目录/数据；聪明钱备份按钮导出自身全量已存快照。文件名及说明明确区分，二者各自留存。原始XML、设置、密钥不随数据备份导出。
